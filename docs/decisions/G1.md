## Budget

The harness prints its own estimate before a live run (`pnpm eval --provider live …`). For 10 ideas × 2 markets (20 drafts) it comes to about **$5** when every draft passes at the first review, about **$11** when each draft is rewritten twice, and **$0.5** more for the judge; the target of G1 is at most $2 per idea. The token sizes behind it are assumptions and thinking tokens are billed as output, so plan for **$10–25** and read the real cost from the first idea (`--cases <id>`, about $0.5–1) before running the rest. Extracting the cards from the two sources and generating the ideas come on top and depend on the number of pages. Levers: run the judge on part of the cases, or on a cheaper model; start with the pilot below.

**Measured in the pilot (2026-10-09, below):** $0.68 per idea for the pipeline, about 1.5 × the harness's typical estimate, so 10 ideas cost about **$7** without the judge (about $8 with it), plus the rewrites and the cards' extraction.

## Stage 0 · Pilot (before the formal run)

Not a gate and not recorded as one: a cheap run that catches gross problems before the reviewers' time is spent, and the place to tune prompts, market notes, voice examples and thresholds. 4 ideas, one source, about 15 cards; `pnpm eval --provider live --set <pilot cases> --judge --g1` (about $2–5). Fix what it shows. **Do not use the pilot's ideas in the formal run**: a prompt tuned on the same ideas proves nothing. What a pilot cannot show: the thresholds of G1 (with 4 ideas one failure is 25 %), the variety of two sources (rights, style, extraction quality), the idea generator's repeat protection (the pool is small) and the spread of native reviewers' scores.

Numbers only: the pilot's texts come from the chef's own guide and stay out of git.

| | |
|---|---|
| Source | 1 guide (18 pages): 81 cards extracted, **14 approved** by the owner (8 grains, 5 techniques, 1 equipment; none safety-sensitive, few with numbers) |

| Repairs and rewrites | 1 draft rewritten once after the critic; 1 writer answer invalid and repaired automatically |
| Comparison of markets | 0 FAIL; 1 pair WARN (same template order), cleared after a regeneration |
| Cost | **$2.83** for the 4 ideas = **$0.68 per idea** (plan $0.10, draft $0.13, review $0.08 per market on average, repairs and the rewrite included); one regeneration of a variant $0.36 |
| Human read | the owner read all 8 drafts; one English hook was weak and was fixed by regenerating that variant with an instruction (quality 4.37 → 4.79, no flags) |

What it showed:
1. **The critic did not catch a weak hook.** An English hook that was a general statement, not a hook, passed with 4.37. Only the human read caught it. The critic has no "hook strength" check; follow-up M2-12a. For G1 this means criterion 4 (voice, usefulness) depends on the human read, not on the critic's score.
2. **Cost is higher than the estimate** (1.5 ×), still far below the $2 per idea target.
3. **A regeneration with an instruction works** and fixes a weak field for about $0.36; field-level regeneration (M4) will be cheaper.
4. **A defect found and fixed (M2-13b):** after regenerating one market the other kept a stale comparison and its `DUPLICATION_RISK` flag.
5. **The pilot did not exercise** the safety flag (no safety-sensitive card was approved), numeric fidelity (few numbers) or the offers (none active), and one source hides rights and extraction variety. The formal run needs a second source with numbers and some safety-sensitive cards.
6. **Operations, not quality:** the Vercel deployment cannot start jobs yet (the Trigger.dev key does not match an environment: `401 No matching branch env`), and its database URL had to move from the transaction pooler (port 6543) to the session pooler (port 5432) because the transaction pooler stalled concurrent queries (decision log 2026-10-08). The pilot ran locally.

The pilot's four ideas are not to be reused in the formal run.

## How to run it

1. Run the pilot first (stage 0), then write the 10 ideas of the formal run, fresh ones, as eval cases outside git (format: `evals/src/case.ts`; see `evals/sets/synthetic` for the shape) or generate the ideas in the app, accept them and generate the drafts on `/content/review/[ideaId]`. Both paths use the same pipeline.
2. Machine checks and the blind sheet:
   ```bash
   pnpm eval --provider live --set /path/to/g1-cases --judge --blind --g1
   ```
   It prints the cost estimate and asks first. The results JSON, the blind sheet (`*-blind.md`, `*-blind.csv`) and the key (`*-blind-key.json`, **not for the reviewers**) land in `evals/results/`.
3. Give each native reviewer the Markdown and the CSV; they fill `reads_as_native_1_5`, `not_a_translation_of_the_other_yes_no`, `approvable_yes_no`, `field_edits_needed`.
4. Ihor and Sergey open each idea on the review screen and rate "approvable with ≤ 3 field edits".
5. Fill the table below, decide, write the actions.

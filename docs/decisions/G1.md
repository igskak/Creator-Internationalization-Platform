## Budget

The harness prints its own estimate before a live run (`pnpm eval --provider live …`). For 10 ideas × 2 markets (20 drafts) it comes to about **$5** when every draft passes at the first review, about **$11** when each draft is rewritten twice, and **$0.5** more for the judge; the target of G1 is at most $2 per idea. The token sizes behind it are assumptions and thinking tokens are billed as output, so plan for **$10–25** and read the real cost from the first idea (`--cases <id>`, about $0.5–1) before running the rest. Extracting the cards from the two sources and generating the ideas come on top and depend on the number of pages. Levers: run the judge on part of the cases, or on a cheaper model; start with the pilot below.

## Stage 0 · Pilot (before the formal run)

Not a gate and not recorded as one: a cheap run that catches gross problems before the reviewers' time is spent, and the place to tune prompts, market notes, voice examples and thresholds. 4 ideas, one source, about 15 cards; `pnpm eval --provider live --set <pilot cases> --judge --g1` (about $2–5). Fix what it shows. **Do not use the pilot's ideas in the formal run**: a prompt tuned on the same ideas proves nothing. What a pilot cannot show: the thresholds of G1 (with 4 ideas one failure is 25 %), the variety of two sources (rights, style, extraction quality), the idea generator's repeat protection (the pool is small) and the spread of native reviewers' scores.

## How to run it

1. Run the pilot first (stage 0), then write the 10 ideas of the formal run, fresh ones, as eval cases outside git (format: `evals/src/case.ts`; see `evals/sets/synthetic` for the shape) or generate the ideas in the app, accept them and generate the drafts on `/content/review/[ideaId]`. Both paths use the same pipeline.
2. Machine checks and the blind sheet:
   ```bash
   pnpm eval --provider live --set /path/to/g1-cases --judge --blind --g1
   ```
   It prints the cost estimate and asks first. The results JSON, the blind sheet (`*-blind.md`, `*-blind.csv`) and the key (`*-blind-key.json`, **not for the reviewers**) land in `evals/results/`.
3. Give each native reviewer the Markdown and the CSV; they fill `reads_as_native_1_5`, `not_a_translation_of_the_other_yes_no`, `approvable_yes_no`, `field_edits_needed`.
4. Ihor and Sergey open each idea on the review screen and rate "approvable with ≤ 3 field edits".
5. Fill the table below, decide, write the actions.
